# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure during this session.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Windows Terminal ConPTY blocks all classic Win32 console interception — `GetSystemMenu` returns NULL, `SetConsoleCtrlHandler` CTRL_CLOSE_EVENT terminates process regardless of return value, and `SetWindowLongW(GWL_EXSTYLE)` has no effect on Windows Terminal windows. The ONLY working approach is to launch via `conhost.exe --` to bypass Windows Terminal entirely.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| CTRL_CLOSE_EVENT veto assumption | Assumed returning `True` from SetConsoleCtrlHandler handler suppresses process termination. It does NOT — Windows terminates the process regardless after cleanup time. | blocking | Do not attempt CTRL_CLOSE_EVENT interception for window close prevention |
| GetSystemMenu cross-process assumption | Assumed GetSystemMenu works on any HWND cross-process. Returns NULL for Windows Terminal windows. | blocking | Check h_menu != 0 before use; log diagnostic if NULL |
| CREATE_NEW_CONSOLE ≠ classic console | Assumed CREATE_NEW_CONSOLE spawns conhost.exe. On Windows 11 with WT as default terminal, it opens a new Windows Terminal tab/window instead. | advisory | Use `conhost.exe -- <cmd>` explicitly to guarantee classic console |
