- [x] **PORT-03**: Cost calculations use `~/.claude/statusline.jsonl → cost.total_cost_usd` — Phase 1 complete (2026-05-08)
- [x] **PORT-04**: Terminal dashboard renders correctly in Windows Terminal (explicit console width, VTP, UTF-8) — Phase 1 complete (2026-05-08)

### Threshold Detection

- [x] **THRS-01**: Tool infers the daily included-token limit via P90 percentile of historical sessions — Phase 2 complete (2026-05-08)

- [x] **THRS-03**: User can manually set the included-token threshold via config to override P90 — Phase 2 complete (2026-05-08)

### Overage Pool

- [x] **OVGE-02**: Dashboard shows estimated dollars spent from the $500 overage pool in current billing month — Phase 3 complete (2026-05-08)
- [x] **OVGE-03**: Dashboard shows percentage of the $500 pool remaining as a visual progress bar — Phase 3 complete (2026-05-08)
- [x] **OVGE-04**: Dashboard shows $/hr burn rate and projected time until pool exhaustion — Phase 3 complete (2026-05-08)
- [x] **OVGE-05**: Pool spend state persists to a local file across dashboard restarts — Phase 3 complete (2026-05-08)
- [x] **OVGE-06**: Pool size (default $500) and billing cycle start date are user-configurable — Phase 3 complete (2026-05-08)

### Display

## v2.0 Requirements (Completed 2026-05-19)

### Cookie Authentication

- [x] **AUTH-01**: Tool automatically extracts the sessionKey cookie from Firefox (primary) or Chrome/Edge (best-effort) — Phase 4 complete (2026-05-19)
- [x] **AUTH-02**: When auto-extraction fails, user can paste a sessionKey value; key stored in Windows Credential Manager via `keyring`, NOT in plaintext config — Phase 4 complete (2026-05-19)
- [x] **AUTH-03**: Stored sessionKey persists across restarts; user not re-prompted if valid key exists in Credential Manager — Phase 4 complete (2026-05-19)

### Web Data

- [x] **WEBD-01**: Dashboard shows authoritative 5-hour window utilization % from claude.ai API, labeled "via claude.ai" — Phase 4 complete (2026-05-19)
- [x] **WEBD-02**: Dashboard shows time remaining until current 5-hour usage window resets — Phase 4 complete (2026-05-19)
- [x] **WEBD-03**: When web data unavailable, dashboard falls back to "(est. — web unavailable)"; no crash, no blank display — Phase 4 complete (2026-05-19)

### System Tray

- [x] **TRAY-01**: Persistent system tray icon — green (<50%), yellow (50–75%), red (≥75%) — Phase 5 complete (2026-05-19)
- [x] **TRAY-02**: Tooltip shows current utilization % and last web sync time — Phase 5 complete (2026-05-19)
- [x] **TRAY-03**: Right-click menu with "Open Dashboard" + "Quit"; Quit = clean shutdown — Phase 5 complete (2026-05-19)
- [x] **TRAY-04**: Left-click toggles terminal window visible/minimized — Phase 5 complete (2026-05-19) *(known limitation: HWND resolution when launched inside shell)*
- [x] **TRAY-05**: Tray icon removed cleanly on exit — no ghost icons — Phase 5 complete (2026-05-19)

### Polling & Reset

- [x] **POLL-01**: Background WebPoller re-fetches every 5 minutes; dashboard shows "Last web sync: HH:MM:SS" — Phase 4 complete (2026-05-19)
- [x] **POLL-02**: Pool spend resets to $0.00 at billing cycle start; reset logged to console — Phase 4 complete (2026-05-19)

### Per-Project Breakdown

- [x] **PROJ-01**: Dashboard shows per-project folders ranked by tokens today (UTC), "est." prefix — Phase 6 complete (2026-05-19)
- [x] **PROJ-02**: Dashboard shows per-project folders ranked by tokens this billing month, "est." prefix — Phase 6 complete (2026-05-19)
- [x] **PROJ-03**: Per-project data is exclusively from JSONL — never merged with web data — Phase 6 complete (2026-05-19)
