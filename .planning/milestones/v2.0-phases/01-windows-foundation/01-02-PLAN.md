<objective>
Replace the upstream Unix path assumption in `data/reader.py` with the correct Windows
AppData path (per D-03). Add PermissionError/WinError 32 handling so a locked active-
session JSONL file is skipped gracefully with a visible dashboard indicator (per D-05).
Also harden JSONL file opens against CRLF and UTF-8 BOM issues (from PITFALLS.md).

Purpose: Without these fixes the tool silently finds zero session files on Windows, and
crashes or hangs when Claude Code holds a write lock on the current session's JSONL file.

Output: `data/reader.py` with Windows-correct path, skip-and-report PermissionError
handling, and CRLF-safe file opens.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JSONL files → Python parser | Files on local disk parsed as JSON; malformed/adversarial content possible if another process writes to the .claude directory |
| os.environ["APPDATA"] | Environment variable from the OS; trusted on a managed Windows machine but can be spoofed by parent process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | JSONL file parsing | mitigate | All json.loads() calls are wrapped in try/except json.JSONDecodeError; malformed lines are skipped, not executed |
| T-02-02 | Information Disclosure | APPDATA path resolution | accept | Path resolves to the current user's own AppData directory; no cross-user access is performed |
| T-02-03 | Denial of Service | WinError 32 file lock | mitigate | PermissionError is caught per D-05; locked file is skipped for this refresh cycle rather than blocking the read loop |
| T-02-04 | Tampering | Path traversal via APPDATA value | mitigate | APPDATA is resolved via os.environ on a managed Windows 11 Enterprise machine; the resulting path is validated to exist via Path.exists() before glob |
</threat_model>

This task modifies data/reader.py in two ways:

--- PART A: PermissionError / WinError 32 handling (per D-05) ---

Find the file-reading loop in reader.py. It will contain something like:
  for jsonl_file in data_path.rglob("*.jsonl"):
      with open(jsonl_file, ...) as f:

Wrap the open() call (and all file-reading code inside it) with:
```python
LOCKED_FILES = []   # module-level list, reset at each read call

# Inside the read loop:
try:
    with open(jsonl_file, 'r', encoding='utf-8-sig', newline='') as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            try:
                entry = json.loads(line)
            except json.JSONDecodeError:
                continue  # skip malformed/truncated lines
            # ... existing entry processing ...
except PermissionError:
    # WinError 32: Claude Code holds a write lock on the active session file.
    # Skip this file for this refresh cycle and record it so the UI can show
    # the indicator per D-05.
    LOCKED_FILES.append(jsonl_file)
    continue
```

The `LOCKED_FILES` list must be accessible to the UI layer. Expose it either:
  - As a return value alongside the session data (preferred if the return type allows it)
  - As a module-level variable `data.reader.LOCKED_FILES` that the UI reads after each call

The exact wording for the dashboard indicator (from D-05) is:
  "(active session — data not yet visible)"
This string does NOT need to be in reader.py — it will be rendered in the UI (Plan 05).
reader.py only needs to communicate THAT a file was locked, not how to display it.

--- PART B: CRLF-safe and BOM-safe file opens ---

The `open()` call for JSONL files MUST use:
  open(jsonl_file, 'r', encoding='utf-8-sig', newline='')

Explanation:
  - `encoding='utf-8-sig'` silently strips UTF-8 BOM if present (PITFALLS.md minor risk)
  - `newline=''` disables universal newline translation so \r\n is preserved as-is
  - `line.strip()` (already added above) then removes \r\n correctly

Do NOT use `encoding='utf-8'` (misses BOM). Do NOT open in binary mode.

--- PART C: Null-field safety ---

Ensure all field accesses on parsed JSON entries use `.get()` with defaults:
  WRONG:  entry["message"]["usage"]["input_tokens"]
  RIGHT:  entry.get("message", {}).get("usage", {}).get("input_tokens", 0)

If the upstream already uses safe .get() access, no change needed — just verify.
