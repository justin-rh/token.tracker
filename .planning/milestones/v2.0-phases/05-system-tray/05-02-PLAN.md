<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pystray menu callback thread → main thread | _quit() and _tray_shutdown() cross from pystray's win32 message loop thread to the main thread via os.kill(CTRL_C_EVENT) |
| on_data_update (MonitoringThread) → TrayManager | tray_manager.update() called from MonitoringThread; Lock in TrayManager protects icon property assignments |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Information Disclosure | _tray_shutdown() / cli/main.py | accept | Function only calls os.kill(pid, CTRL_C_EVENT). No data exposure. The session_key is already in keyring (D-04, 04-06 plan) and is never passed to TrayManager — confirmed: TrayManager receives only utilization_pct (float) and last_sync (datetime). |
| T-05-07 | Denial of Service | tray_manager.stop() absent from finally | mitigate | stop() is guarded with `"tray_manager" in locals() and tray_manager is not None` — identical to web_poller pattern already verified in Phase 4. Covers all exit paths: KeyboardInterrupt, unhandled Exception, normal return, and Quit menu (icon.stop() called before CTRL_C_EVENT). |
| T-05-08 | Tampering | on_data_update reading monitoring_data["web_usage"] | accept | monitoring_data is produced by the trusted MonitoringOrchestrator on the same machine. web_usage.utilization_pct is a float from the already-validated WebUsageData frozen dataclass. No external input crosses this boundary. |
</threat_model>
